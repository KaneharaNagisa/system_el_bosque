# Copilotの過去のミス・注意点メモ

※Copilotが仕様を間違えるたびに、ここに1〜2行で書き足していきます。

- [ ] APIのレスポンス形式を勝手に `{ data: ... }` に変えようとした。正しくは `{ success: true, result: ... }`。
- [ ] 日本語のエラー文言を勝手に英語に変えてしまった。
- [ ] 1～５名は一棟貸しの料金が変わらないのに、１～５名の人数によって料金を加算してしまった。
- [ ] Googleカレンダーの予定ありなしを管理画面＞マスタ管理＞予定枠管理に反映してほしいと依頼したときに、Googleカレンダーの予定名なども反映しようとした。
- [ ] Google から返ってきたデータの中に、決定的な原因となるプロパティがありました。※１参照
- [ ] 管理画面＞マスタ管理＞予約枠管理で「空きあり」の日付にGooglaカレンダーの予定があった場合は、Googleカレンダーの予定を優先してください。  
けれど、すでに予約が入っている日付にGoogleカレンダーの予定が入っている場合は、注意のアラートを表示し、管理者へメールを送信してください。


## ※１

```json
"transparency" => "transparent"
```

### 原因の解説
Google カレンダーの予定には **「予定あり（busy / opaque）」** と **「日時の空き時間（transparent / 予定なし）」** の2つの表示設定があります。

* **終日（all-day）予定** を作成すると、Google カレンダーはデフォルトで **「空き時間（transparent）」** として登録することがよくあります。
* システム側の `GoogleCalendarSyncService` は、**「空き時間（transparent）」扱いの予定は枠をブロックせず無視する（または busy のものだけ抽出する）** というロジックになっている可能性が非常に高いです。

---

### 解決策（どちらかで直ります）

#### 方法1: Google カレンダー側の設定変更（一番かんたん）
1. Google カレンダーで **2026/09/25 の「テスト予定」** をクリックして編集画面（えんぴつアイコン）を開きます。
2. **「予定あり / 空き時間」** の設定（通常、カレンダー名や色の選択肢の近く、あるいは通知設定のあたりにあります）を確認します。
3. **「空き時間」** になっている場合は、**「予定あり」** に変更して保存してください。

#### 方法2: サービス側の判定ロジックの確認
`eventDates` メソッドでどのようにフィルタリングしているか確認してみましょう。
Tinker で以下を実行してみてください：

```php
$refEv = new ReflectionMethod($svc, 'eventDates'); $refEv->setAccessible(true); dump($refEv->invoke($svc, ['start' => ['date' => '2026-09-25'], 'end' => ['date' => '2026-09-26'], 'transparency' => 'transparent', 'status' => 'confirmed']));
```

Google カレンダー側の設定を「予定あり」に変更した上で、再度同期コマンドを実行すれば、確実にブロック対象として反映されるはずです！
